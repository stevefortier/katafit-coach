# Operator dojo check-in photos: backend contract and deployment boundary

The unified Operator opens `{mode:"dojo_operator",idempotency_key}` without `member_ref`; the backend response has no top-level `member_ref`. It advertises the roster and only the currently allowed subset of member reads, send, and check-in tools. The model supplies `member_ref` on each per-member call. The Kata.fit backend must be merged/deployed separately before live Studio can display dojo check-in cards. See [unified contract](operator-unified-contract.md).

For every turn Coach attempts the negotiated unified Operator capability. A missing catalog degrades to tool-free conversation; failed authorization is not treated as granted access. Actual successful read or attempted send execution, **not model prose or keyword matching**, makes that reply ephemeral: no member-derived reply is saved to `operator-chat.json` or replayed into a later turn. Each later question must reacquire current sharing authority and data. Clear, cancel, lock, config/credential change, or process exit remove transient image cards.

The validated image tool result can create a transient Studio card with the authorized roster's bounded display name and media date (not an asserted completion date). Vision models receive native image bytes; text-only models receive bounded metadata and an explicit “not visually assessed” receipt while the same backend-validated result creates a visible card. At most four originals / 16 MiB per turn are copied into process memory for two minutes. Chat JSON carries only opaque card IDs and bounded display labels/dates; it carries no media bytes, backend refs, or data URLs. The authenticated no-store binary endpoint opens a **fresh dojo_operator session**, checks the current authorized check-in roster and reads the original under backend authority, then matches MIME, signature, dimensions, SHA-256, and bytes to the turn image before returning. It never chooses an arbitrary member anchor. Clear/cancel/new turn invalidates cards and the browser revokes Blob URLs. Browser cards are never parsed from model text.

Limits: four image blocks per inference, 16 MiB aggregate bytes, 8 MiB per original, 12 model tool calls, 256 KiB cumulative text output. A ten-member page can leave more pages; an authorized image ref listed but never fetched also produces a partial-coverage notice independent of model prose. This is not proof of a full-roster audit, even if the visible page has no continuation. Synthetic tests establish transport and authorization guards, **not** real-provider compliance with coverage instructions or live backend publication.
