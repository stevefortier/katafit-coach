# Unified Operator contract (standalone ↔ Kata.fit backend)

Standalone POST `/api/operator/chat` accepts exactly `{text}`. It opens `{mode:"dojo_operator",idempotency_key}` without a member_ref. The backend returns an active session with no member_ref and `allowed_tools`; `studio_operator_list_members` is mandatory for identity resolution. Only the intersection of finite recognized manager tools and the advertised `tools/list` is model-exposed; send, photo and activity tools are optional, based on backend scopes. Expected recognized names: `studio_operator_list_members`, `studio_operator_list_dojo_checkins`, `studio_operator_read_dojo_checkin_image`, `studio_operator_read_member_coach_feed`, `studio_operator_list_activities`, `studio_operator_read_activity`, `studio_operator_send_message`. The first is a current authorized roster with opaque member_ref; per-member reads/sends require `member_ref` in each call (the model chooses an unambiguous ref from the roster, including multiple different members per turn). Backend is sole access authority and must enforce current chief/credential/sharing at every call, no host preselection. Send args `{session_id,idempotency_key,member_ref,text}`; one send maximum per session; delivered receipt/uncertainty reconciled through `studio_operator_get_action`; close session. No arbitrary MCP/worker lease/settings writes, no inferred permission from roster existence. Per-member tools may be omitted from allowed_tools if backend does not authorize that capability. Preserve bounded calls/images, ephemeral derived output, grant revocation. Backend pair should verify two-target reads, denied domains and one send.
