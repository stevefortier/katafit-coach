# Generic trainee-media to native Operator panel: integration boundary

This Coach integration pairs with the backend contract in [regimen PR #861](https://github.com/stevefortier/regimen/pull/861); deployment and live acceptance are separate release gates. The backend's signed references bind current credential/member/category/Clear and activity/file identity, but it does **not** persist a strict same-session list/detail receipt. The Coach additionally requires successful exact in-session list/detail evidence before dispatching pixels; backend authority remains decisive. A successful `studio_operator_read_activity({section:'media_files'})` returns metadata and opaque `media_ref`, not pixels. `send_to_operator({image_receipt})` accepts only a host-minted receipt of validated bytes in this native runtime; `workspace_path` cannot safely fetch backend media. The existing `studio_operator_read_dojo_checkin_image` permits exact pairs from a successful check-in listing, not arbitrary activity media references. Do not pass an activity `media_ref` as an `image_receipt` or as a check-in ref.

Backend companion contract: negotiate `studio_operator_read_activity_image` only with `history:read`, `userdata:read`, `media:read`. Call with host-owned `session_id` and current `turn_generation` plus the exact `member_ref`, `activity_ref` from an authorized activity listing and `media_ref` from that activity's `media_files` page. Backend reauthorizes current member/category/source and verifies both references resolve to the **same completed media activity**, validates the file, and returns `{structuredContent:{schema_version:1,representation:'original',mime_type,byte_count,sha256,width,height},content:[{type:'text',text:JSON.stringify(structuredContent)},{type:'image',mimeType,data:canonicalBase64}]}`. No URL, host path or file ID is supplied to the model. A successful result is only a pixel receipt, not proof the human saw it. Check-in's latest-completed rule remains independent. The Coach native adapter supports the dojo-wide continuity session; it does not advertise this image adapter to legacy selected-member sessions.

Coach integration now uses the separately negotiated image-read tool: advertises it only when backend catalog and session capability agree; strips host-owned fields before schema validation; requires prior successful exact activity list/detail pairs retained only for the current generation; dispatches raw bounded MCP multipart and applies the existing original-image MIME/base64/hash/dimension and shared per-turn image capacity checks. Validated bytes mint per-runtime `ImageReceipts`; `send_to_operator` performs fresh backend authorization and publishes to the attachment panel. Revocation tears down receipts/attachments. Synthetic loopback coverage verifies exact pair, malformed multipart, revocation, and receipt-to-panel flow. Release qualification includes exact combined backend+Coach builds against the backend Mongo/MCP harness and a real isolated Pi with the installed native image and browser attachment panel; local synthetic fixtures alone do not establish deployed acceptance.

The historical read failure's exact code and arguments have not been captured safely. HTTP 200 with MCP `tool_error` establishes only backend refusal. A fresh isolated context read succeeds; a deliberately invalid `activity_ref` returns `OPERATOR_NOT_AUTHORIZED` at a similar response size, but length is not an identity proof. A deterministic backend Mongo test shows a changed previously retained source denies subsequent reads in the old continuity session while a fresh independent session succeeds; that proves a possible mechanism, not the historical cause. Ordinary invalid-reference denials receive fixed read-only guidance; a definite `context_revoked` signal or failed retained-context reauthorization tears down the runtime and requires a fresh session. This bridge neither retries nor grants media access.
